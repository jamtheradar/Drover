# Drover 0.7.0

Agent-aware specs. 0.6.0's Agents view was an inventory with a liveness
light — it knew which subagents existed and which were running, but nothing
about the work. This release wires it to the spec pipeline: a spec can name
the agent that implements it and the reviewer whose concurrence gates
`done`, the Specs panel can dispatch a single spec at a chosen agent, and
the Agents rail shows each agent's spec workload. All of it rides on two new
frontmatter fields — no new state, no new session↔Drover signal.

## Highlights

- **`agent:` frontmatter** — a spec can name the subagent that should
  implement it. Drover parses the field, substitutes it into `execute-spec`,
  and the prompt delegates via the Task tool; the calling session keeps
  ownership of the frontmatter so a subagent can't race the loop runner. An
  empty or unrecognised value falls back to implementing in-session, which
  stays the common case. `promote-interrogate` now reads the descriptions of
  the agents it discovers and proposes the best fit rather than leaving the
  field blank.
- **`verify_with:` reviewer gate** — names an independent reviewer that must
  pass every acceptance criterion before `status: done` may be written.
  Previously `execute-spec` graded its own homework, which is the weakest
  link in an overnight batch: one unearned `done` and the runner advances.
  A verifier-driven failure reaches Drover as an ordinary
  `blocked` + severity, indistinguishable from any other — the existing stop
  policy already covers it. A missing or unknown reviewer degrades to
  self-assessment and says so; it never blocks a run on its own.
- **Specs panel: run one spec, or dispatch it at an agent** — right-click any
  row for **Run this spec** (one spec, project default loop mode, checkbox
  selection untouched) and **Run with agent ▸** (that spec against a chosen
  agent). Dispatch is routed through the loop runner rather than a raw send,
  so it still gets status watching, the progress strip, the per-spec timeout,
  and Stop. The agent choice is per-run — nothing is written back to the
  file. Forced to Drover-driven mode, since a single-agent override is a
  single-spec concept.
- **Agents rail shows spec workload** — each agent card in the Kanban Agents
  view now carries a `{done}/{assigned} specs` count, the id chips of the
  specs assigned to it, and a marker for the one currently `in-progress`.
  All derived from `specs/*.md` frontmatter, so it's true whether Drover
  started the run or you typed the prompt by hand. Agent cards expand for
  the first time; Local and Live cards are unchanged.
- **Initialize specs seeds starter agents** — *Project ▸ Drover ▸ Initialize
  specs* now also writes `.claude/agents/spec-implementer.md` and
  `spec-reviewer.md` alongside the `.drover/` templates, so `agent:`,
  `verify_with:`, and **Run with agent** have something to resolve against
  on a fresh project instead of an empty submenu. Both are generic starting
  points meant to be edited, and an existing agent of the same name is left
  alone — `.claude/` isn't Drover's directory.

## Notes

- The two new frontmatter fields are free strings with no validation against
  the agent catalog, matching the existing posture for `estimate`. An
  unknown agent name is the prompt's problem to report, not Drover's to
  police.
- Specs written before 0.7.0 parse unchanged — both fields default to empty,
  which is the pre-0.7.0 behaviour exactly.
- Drover never rewrites `.drover/`, so a project initialized before 0.7.0
  keeps its existing `spec-template.md`. Add the `agent:` and `verify_with:`
  lines by hand, or delete the file and re-run Initialize specs to pick up
  the new default.
